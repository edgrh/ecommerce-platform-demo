## 一、项目概况

### 1. 项目背景

随着移动互联网与线上零售的普及，高并发场景下的库存准确性与交易一致性成为电商系统的核心难点。传统单机数据库在瞬时流量下易出现行锁竞争、连接池耗尽与超卖风险；若缺乏分布式缓存与协调机制，系统既难以横向扩展，也难以在故障时快速降级。Redis 作为内存型键值存储，在业界广泛用于缓存、分布式锁、计数器与限流等场景，是理解现代分布式架构的重要一环。

本课程设计实现一套**电商 + 秒杀**演示系统：买家浏览商品、购物车结算、参与秒杀下单并查看订单；商家上架商品并查看关联订单。系统在技术栈上引入 **Redis** 承担秒杀库存预减、购物车会话、网关限流键、分布式锁与热点数据缓存等职责，与 **MySQL** 持久化、**RabbitMQ** 异步消息、**Elasticsearch** 检索等组件协同，形成接近真实业务的简化链路。完成本项目有助于理解：**为何要在数据库前加一层内存协调**、**如何避免超卖**、**如何在网关与业务层做治理**，对掌握分布式技术中的**一致性、可用性、分区容错**等概念具有直接意义。对社会而言，同类技术支撑了日常网购、票务与营销活动，降低交易纠纷与系统瘫痪风险，具有广泛工程价值。

（本节约 **560 字**，满足 300～700 字要求。）

## 二、技术方案

### 1. 技术方案描述

整体采用 **B/S 架构**：前端 **Vue3 + Vite** 单页应用，经 **Nginx**（云上）或开发代理访问 **Spring Cloud Gateway**；网关统一路由、CORS、限流与熔断；业务服务 **Spring Boot + MyBatis** 访问 **MySQL**；**Redis** 作为分布式协调与缓存；**RabbitMQ** 承载异步消息；**Elasticsearch** 提供中文分词检索（可回退 MySQL）。部署上支持 **Docker Compose 单机**与 **Kubernetes 清单**多副本，便于本地答辩与扩展叙述。

（本节约 **210 字**，满足 100～500 字要求。）

### 2. 某技术功能：Redis 在本项目中的作用

**Redis** 在本系统中不是“可有可无的缓存”，而是贯穿秒杀与治理的关键组件，主要体现在：

1. **秒杀库存预减**  
   高并发下若直接对 MySQL 行锁扣减，延迟与锁竞争会急剧上升。系统先将活动剩余库存放在 Redis 计数结构中预占，成功后再在事务内更新数据库与 SKU 库存；失败或异常时**释放预占**，降低数据库瞬时压力并减少超卖窗口。

2. **购物车**  
   买家购物车以 **Redis Hash** 按用户维度存储 `skuId -> quantity`，读写快、易过期清理，与无状态 JWT 配合形成常见的会话外置模式。

3. **网关限流**  
   Spring Cloud Gateway 的 **RequestRateLimiter** 使用 Redis 记录令牌桶或窗口计数，实现按 IP 的入口限流，防止恶意刷接口拖垮下游。

4. **分布式锁**  
   秒杀下单路径上使用 Redis 实现的锁（如按用户维度），避免同一用户并发请求穿透到重复扣减逻辑，保证临界区互斥。

5. **热点缓存**  
   商品上架列表等读多写少数据可缓存到 Redis，减轻数据库与检索压力；商品变更时主动失效缓存。

6. **与 CAP 的关联（简述）**  
   Redis 集群在工程上常作为**高可用缓存层**；业务上通过“预减 + DB 事务”在**一致性**与**性能**之间折中，体现分布式设计中典型的工程权衡。

综上，Redis 同时承担**性能加速、并发控制、流量治理**三类职责，是理解“分布式系统为何需要共享状态中间件”的合适切入点。

（本节约 **620 字**，满足 500～1000 字要求。）

## 三、实现流程

### 步骤一：环境与基础中间件

1. 安装 **JDK 17、Maven、Docker、Node.js**，克隆仓库。  
2. 执行 `docker compose up -d` 启动 **MySQL、Redis、RabbitMQ、Elasticsearch**（首次需按文档构建 ES 镜像以启用 IK）。  
3. 确认端口映射与 `application.yml` 中数据源、Redis 地址一致（如 MySQL 宿主机 **3308**、Redis **6380**）。

### 步骤二：后端与网关构建运行

1. 根目录执行 `mvn -DskipTests package` 生成 `bcommerce-commerce`、`bcommerce-gateway` 可执行包。  
2. 先启动 commerce（默认 **8081**），再启动 gateway（**8080**），或通过 **Kubernetes** 清单部署多副本。  
3. 访问 `http://127.0.0.1:8080/actuator/health` 验证网关；访问 `/api/c/products` 验证业务穿透。

### 步骤三：前端构建与联调

1. 在 `frontend` 目录执行 `npm ci` 与 `npm run dev`（开发）或 `npm run build` 后由 **Nginx** 托管静态资源。  
2. 配置同源代理：`/api` 转发到网关，避免浏览器 CORS 问题。  
3. 使用演示账号登录买家/商家，走通**浏览—加购—支付—订单**与**秒杀—订单**全链路。

### 步骤四：秒杀与 Redis 路径验证（可选写进报告）

1. 打开秒杀页，确认活动列表与库存展示；使用买家账号发起抢购。  
2. 观察 commerce 日志：Redis 预减、数据库事务、支付 mock（含熔断演示配置）是否按设计执行。  
3. 在「我的订单」与「商家后台」核对订单号、金额、类型标签是否一致。

### 步骤五：云上部署与答辩演示（可选）

1. 参考 `docs/CLOUD-DEPLOY.md`：云主机安装 Docker、JDK、Maven、Nginx，`git pull` 后执行一键脚本或手动 `mvn package`、双进程、`npm run build` 发布。  
2. 安全组放行 **80/22**；公网通过 `http://<IP>/` 访问。  
3. 如需强调**集群化**，补充阅读 `docs/K8S-CLUSTER.md` 与 `k8s/` 多副本清单。

（本节约 **980 字**，满足 800～1500 字要求。）

### 核心代码摘录（不超过两页，不计入上述字数）

```java
// Redis 预占失败则快速返回；成功后再进入 DB 事务更新 sold 与 SKU 库存
Long redisOutcome = stockRedis.reserve(act.getId(), req.quantity());
if (redisOutcome == null || redisOutcome == -1L) {
    stockRedis.refreshActivity(act.getId());
    redisOutcome = stockRedis.reserve(act.getId(), req.quantity());
}
if (redisOutcome == -2L) {
    throw new ResponseStatusException(HttpStatus.CONFLICT, "Insufficient stock");
}
// 后续 tryIncreaseSold、订单写入、异常时 stockRedis.release(...)
```

## 附录：常见答辩问题要点（简答）

1. **分布式核心特征**：扩展性、并发与容错、组件解耦、存在网络分区与延迟。  
2. **HDFS 原理架构**：NameNode 管元数据，DataNode 存块，多副本容错。  
3. **通信模型**：客户端-服务器、发布-订阅、点对点消息等。  
4. **消息传递两种典型模型**：队列（点对点负载均衡）与主题（发布订阅广播/多播）；解耦削峰。  
5. **常见协议**：HTTP/HTTPS、gRPC、AMQP、TCP 等。  
6. **TCP 三次握手/四次挥手**：同步序列号建立连接；关闭时半关闭与 TIME_WAIT。  
7. **HTTP 与 HTTPS**：HTTPS 在 HTTP 下增加 TLS，加密与身份校验。  
8. **通信常见异常**：超时、丢包、乱序、分区、脑裂等。  
9. **CAP**：一致性、可用性、分区容错不可三者全得，需权衡。  
10. **分片策略**：哈希取模、范围分片、一致性哈希等；本项目订单按用户分片。  
11. **ZooKeeper 原理**：ZAB 协议，Leader/Follower，提供协调与配置服务（与本项目无强绑定时可如实说明）。  
12. **分布式事务容错**：重试、幂等、补偿、Saga/TCC 等思路。  
13. **云部署三种方式**：本地/私有云、公有云、混合云（表述可按教材统一）。  
14. **IaaS / PaaS / SaaS**：基础设施、平台、软件三种交付层次。  
15. **Docker 常用命令**：`docker ps`、`docker build`、`docker compose up -d`、`docker logs` 等。
